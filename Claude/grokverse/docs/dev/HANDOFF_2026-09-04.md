## 4. Traps found this week — each cost real time

* **float32 checkpoints vs float64 analysis.** Reconstructions disagree with `common.grid_logits` by
  ~1e-4 on logits of scale ~270; against the same model cast to float64 they agree to ~1e-13. Assert
  both bounds, never just the loose one (`test_transformer_mechanism.check_forward`).
* **A test asserting a property the quantity cannot have.** `acc == 1/p` on annihilated logits
  (argmax of 1e-13 noise), a set-based harmonic share at aliasing collisions (entry 26), a `1/j`
  truncation without its alternating sign (entry 24). When a check fails, first ask whether the check
  is wrong — the module was right in all three cases.
* **`fit_matrix` per-column detection** mistakes a length-4 constant for a per-column array when a
  frequency group has exactly four neurons → use `mlp_mechanism.fit_curve_matrix` (splits per k).
* **Aliasing at p = 113**: the odd-harmonic families of k = 6, 19, 51 land on k = 18, so "the harmonic
  model fits at k" does not identify k as the fundamental (`test_wave_fitting.py`). Bears on H3.
* **Windows MAX_PATH** in temp dirs made a test fail that was not a module bug (entry 23); tests use
  `tempfile.TemporaryDirectory()` with short names.
* **Bash heredocs on this machine** choke on some quoting (apostrophes inside Python strings); for
  multi-line Python patches write a file with the Write tool and run it.
* **The process list shows every training run twice** — `.venv\Scripts\python.exe` is a shim that
  re-executes `Python312\python.exe`. Check parent PIDs before concluding anything is duplicated.
* **`masked_ce_and_acc` needs a `[p, p, p]` grid**; a cheaper `[p, p, 3]` grid is fine for projection
  identities but not for a loss.
* `driver.resolve_runs` only returns runs whose manifest says `completed`; `--workers` defaults to 1.
* `training/results/` is untracked on purpose while the matrix rewrites `run_manifest.*`; commit it
  once the training chain has finished (master prompt §20 requires the manifests in the record).
